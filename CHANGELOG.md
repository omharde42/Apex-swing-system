* Entry
* Stop Loss
* Target 1
* Target 2
* Target 3

once a valid setup has been confirmed.

The objective is to prevent trade levels from continuously changing while a setup is active.

## Versioning

Apex uses the following general version structure:

```text
MAJOR.MINOR.PATCH
```

### MAJOR

Large architectural or feature changes.

Example:

```text
1.x → 2.x
```

### MINOR

New features or substantial improvements.

Example:

```text
1.0 → 1.1
```

### PATCH

Bug fixes, small improvements and stability updates.

Example:

```text
1.0.0 → 1.0.1
```

---

## Release Philosophy

Apex development prioritizes:

**Signal quality → Stability → Validation → Usability → Advanced features**

New features should be added only when they provide meaningful functionality rather than unnecessary complexity.
